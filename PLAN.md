# Справочник по Git и GitHub — карта книги

Продукт отдельный от справочников по Python и MongoDB: своя палитра
(оранжевый Git `#F05133` и угольный) и свои блоки. Автор — Макаров М. Н.

## Принцип порядка

Ни одна кнопка не появляется раньше, чем объяснено, что она делает с историей
проекта. Отсюда порядок: сначала понятия без интерфейса, затем локальная работа
в VS Code, затем ветки, и только после этого GitHub со всей его начинкой.

## Что отложено

Глава «Как Git хранит историю» (снимки, хеш, объекты, три состояния файла)
написана и лежит в `chernoviki/kak-git-hranit-istoriyu`. В первом модуле она
стоит слишком рано: там команды, ветки и внутреннее устройство, а читатель ещё
не сделал ни одного коммита. Место для неё — конец модуля 3, когда ветки и
коммиты уже освоены кнопками и разбор ложится на готовое представление.

**Правило порядка, из которого это следует:** сначала человек делает действие
руками и видит результат, потом узнаёт, как оно устроено внутри. Обратный
порядок превращает главу в набор незнакомых слов.

## Правила оформления

1. **Цифры — только моноширинным шрифтом.** В Pixelify Sans «2» на мелком кегле
   читается как «8»: даты вида «26 июля 2005» превращаются в «86 июля 8005».
   Пиксельный шрифт остаётся для буквенных подписей.
2. **Каждая картинка из интернета — с подписью**: автор, лицензия, ссылка на
   страницу файла. Данные берутся из `img/credits.json`, который заполняет
   `tools/images.py`.
3. **Факты со ссылкой.** В конце главы блок «Откуда взяты факты» с источниками.
4. **Кнопка и команда рядом.** Показываем, где нажать в VS Code, и какая команда
   Git за этим стоит, — но набирать команды не требуем.
5. Тон — по `shared/VOICE.md` справочника по Python: сначала ситуация, потом
   термин; «мы» в объяснении, «вы» в действиях; программа ничего не «понимает».
