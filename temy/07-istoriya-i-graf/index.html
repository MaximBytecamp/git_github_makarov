§1Зачем читать историю

История нужна, чтобы узнать, как и почему менялся проект:

Зачем это нужно в работе

  • Найти коммит с ошибкой. Страница перестала работать после недавних правок. История показывает коммиты за это время, среди них ищут тот, что внёс ошибку.
  • Разобраться в чужом коде. Назначение строки неясно. История показывает, в каком коммите и кем она добавлена, а сообщение коммита объясняет причину.
  • Вернуть удалённый файл. Файл, удалённый месяц назад, остаётся в прошлых коммитах, и нужную версию достают из истории.
  • Отчёт о работе. Список коммитов за неделю показывает, что сделано, с датами и сообщениями.

В главе используется проект sait-vizitka из прошлых глав. В нём шесть коммитов: четыре получены при клонировании, два сделаны в главе 2.3.

1История в VS Code

§2Шаг 1. Открыть раздел Graph

История проекта показана в панели Source Control.

Открываем панель Source Control. Под списком изменений находится раздел GRAPH. Если он слишком узкий, раздел CHANGES сворачивают щелчком по заголовку.

Синяя метка main отмечает коммит, на котором вы стоите. Фиолетовая origin/main отмечает последний коммит копии проекта на GitHub. Два коммита между ними сделаны у вас и на сервер не отправлены.

Строка Outgoing Changes вверху графа объединяет те же два неотправленных коммита.

Что получилось.Видна вся история: шесть коммитов, метки main и origin/main.

§3Шаг 2. Посмотреть, что внутри коммита

Каждый коммит в графе раскрывается в список файлов.

Нажимаем на коммит Добавил страницу контактов. Под строкой появляется список файлов коммита.

По этому списку проверяют, все ли нужные файлы вошли в коммит и нет ли лишних.

Что получилось.Видны файлы коммита «Добавил страницу контактов»: index.html и kontakty.html.

§4Шаг 3. Открыть изменения построчно

Изменения в файле коммита открываются построчно.

Дважды щёлкаем по файлу внутри коммита. Открывается окно сравнения. В нём сравниваются две версии файла: до этого коммита и после него.

Строки из букв и цифр в скобках — имена коммитов: сначала предыдущего, затем открытого. Эти имена разобраны в следующем параграфе.

Что получилось.Видно построчно, что этот коммит изменил в index.html.

§5Справка: имя коммита

У каждого коммита есть имя — длинная строка из букв и цифр, которую Git вычисляет по содержимому. Это хеш. В полном виде он выглядит так:

Обычно используют первые семь символов: 745f2e1. Такие короткие имена показаны в графе, в выводе команд и в заголовке окна сравнения.

Где встречаетсяКак выглядитЧто с ним делают
Вывод git log --oneline745f2e1Копируют, чтобы открыть коммит или откатиться к нему
Заголовок окна сравнения(745f2e1) ↔ (2e4864c)Понимают, какие версии сравниваются
Страница коммита на GitHubcommit 745f2e1Ссылку на страницу отправляют коллеге
Вывод git blame8da3e92eСмотрят, из какого коммита пришла строка
На полях: почему имя не порядковый номер

Для порядковых номеров нужен общий счётчик, а копия истории есть у каждого участника. Хеш вычисляется из содержимого коммита, поэтому один и тот же коммит имеет одно имя на любом компьютере, а изменённый коммит получает новое имя.

Щелчок по строке открывает сравнение файла до коммита и после. Так находят коммит, после которого в файле появилась ошибка.

Что получилось.Видны четыре коммита, которые меняли index.html.

3История на GitHub

§8Шаг 6. История на GitHub

На GitHub хранится копия отправленных коммитов, и историю читают там же. Это нужно, когда проекта нет на компьютере или коллеге отправляют ссылку.

На странице проекта нажимаем счётчик коммитов, например 4 Commits. Открывается список коммитов.

Открыть коммит. Щелчок по сообщению открывает страницу коммита с изменёнными файлами и строками.

История файла. Открываем файл на GitHub и нажимаем кнопку History. Открывается список коммитов, менявших этот файл.

Что получилось.История проекта, отдельный коммит и история файла открыты на GitHub.

§9Шаг 7. Кто написал эту строку

Если назначение строки в файле неясно, перед удалением выясняют, в каком коммите и кем она добавлена.

Открываем файл на GitHub и переключаемся на вкладку Blame.

То же показывает команда git blame. Ключ -L задаёт диапазон строк:

В каждой строке ответа: имя коммита, автор, дата, номер строки и текст. По имени коммита открывают коммит и читают сообщение с причиной правки.

Ассоциация: поля учебника с пометками

В жизни

В учебнике, где пометки оставляли несколько человек, у каждой пометки на полях стоят подпись и дата. По ним видно, кто и когда её сделал.

В Git

Blame подписывает каждую строку файла коммитом, автором и датой. По имени коммита открывается сообщение с причиной правки.

Где не совпадаетПометки на полях сохраняются все, а blame показывает только последнее изменение строки. Если строку позже правил другой человек, blame укажет его. Первоначального автора ищут в более ранних коммитах.

Что получилось.У каждой строки index.html виден коммит, автор и дата.

В длинной истории коммиты отбирают по файлу, автору, слову в сообщении или дате.

5Проверка себя

§11Частые вопросы

Обычно думаютИстория хранится на GitHub, поэтому без интернета её не посмотреть.
На самом делеИстория лежит в папке .git на вашем компьютере. Граф, Timeline и git log работают без сети. Сервер нужен для обмена коммитами.
Обычно думаютЕсли коммита нет на GitHub, значит, он не сделан.
На самом делеКоммит сделан и хранится у вас. На GitHub он появится после отправки. В графе такие коммиты стоят выше метки origin/main, в строке состояния видно число со стрелкой вверх.
Обычно думаютBlame нужен, чтобы найти виноватого.
На самом делеBlame используют, чтобы найти объяснение правки: сообщение коммита и соседние изменения.
Обычно думаютКороткие имена разных коммитов могут совпасть.
На самом делеКороткое имя — первые символы полного хеша. Git показывает столько символов, сколько нужно, чтобы имя было единственным в репозитории. В больших проектах их больше семи.

§12Проверьте себя

В графе метка main стоит выше метки origin/main. Что это значит?

У вас есть коммиты, которых нет на сервере: все коммиты между двумя метками сделаны локально и не отправлены. В строке состояния это показано числом со стрелкой вверх.

Страница перестала открываться. С чего начать разбор по истории?

Посмотреть последние коммиты: git log --oneline или раздел Graph. Затем открыть коммиты, сделанные после последней работающей версии, и посмотреть их состав. Если известен файл с ошибкой, список сужают: git log --oneline -- имя-файла.

Чем Timeline отличается от раздела Graph?

Graph показывает всю историю проекта, Timeline — коммиты, менявшие открытый файл. Тот же отбор делает команда git log -- имя-файла.

В заголовке окна сравнения написано index.html (745f2e1) ↔ index.html (2e4864c). Что с чем сравнивается?

Версия файла из коммита 745f2e1 (слева, более ранняя) с версией из коммита 2e4864c (справа). Подсвечены строки, которые между этими двумя коммитами изменились.

Назначение строки в файле неясно. Каков порядок действий?

Открыть файл на GitHub, вкладка Blame, найти строку и посмотреть коммит слева от неё. Затем открыть этот коммит и прочитать сообщение с причиной правки. На компьютере то же показывает git blame имя-файла.

Почему у коммита имя вида 745f2e1 и нет порядкового номера?

Имя вычисляется из содержимого коммита и не зависит от порядка и от компьютера. У каждого участника своя копия истории, поэтому общего счётчика для номеров нет.

§13Шпаргалка по главе

Где смотреть в VS Code раздел GRAPH — вся история раздел TIMELINE — история файла
Метки в графе main — где вы сейчас origin/main — где сервер
Команды истории git log --oneline --graph git log --oneline -- файл git show --stat хеш
Автор строки вкладка Blame на GitHub git blame -L 9,11 файл
Поиск коммита --author=имя --grep=слово --since=yesterday
Имя коммита хеш, первые 7 символов 745f2e1

Итог главы

Историю проекта читают в нескольких местах, и везде показаны одни и те же коммиты. Раздел GRAPH в панели показывает всю цепочку с метками main и origin/main; щелчок по коммиту раскрывает список файлов, двойной щелчок — построчные изменения. Раздел TIMELINE оставляет только историю открытого файла. Те же данные дают команды git log, git show и git blame. На GitHub история открывается счётчиком коммитов, а вкладка Blame показывает у каждой строки файла коммит, в котором она появилась. Имя коммита — хеш, обычно его сокращают до семи символов. В следующей главе разобраны служебные файлы: как исключить из истории лишние файлы и описать проект в README.
