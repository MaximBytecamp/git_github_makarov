§1Две ситуации: свой проект и чужой

Работа начинается с пустой папки или с готового проекта. В пустой папке историю заводят, готовый проект скачивают вместе с его историей.

Путь А · проект начинаете вы

Кнопка Initialize Repository заводит историю в вашей папке.

  • История пустая: коммитов ноль
  • Интернет не нужен
  • На GitHub ничего пока нет

Путь Б · проект уже существует

Команда Git: Clone скачивает проект целиком: файлы, коммиты, ветки и адрес сервера.

  • История приходит вместе с файлами
  • Нужен интернет и адрес репозитория
  • Связь с сервером настроена сразу

Зачем это нужно в работе

  • Работа в готовом проекте. На новом месте работы первым делом клонируют репозиторий команды. В клоне сразу записан адрес, куда отправлять правки.
  • Своя разработка с первого дня. Репозиторий заводят в начале работы над проектом. Правки, сделанные до этого, в историю не попадут.
  • Изучение чужого кода. Вместе с файлами клонируются все прошлые коммиты. По ним видно, как проект менялся.
  • Копия на другом компьютере. Тот же проект дома и на работе — это два клона одного репозитория. Переносить папку флешкой не нужно.

§2Путь А, шаг 1. Завести репозиторий в своей папке

Путь А: своя папка без истории.

Создаём пустую папку проекта и открываем её в VS Code через File → Open Folder. Затем открываем панель Source Control: CtrlCmd + Shift + G.

Нажимаем Initialize Repository. Подтверждение не требуется, панель меняется сразу:

То же в терминале:

Создание файла, отбор и первый коммит разобраны в главе 2.1. Здесь рассматривается только появление репозитория.

Вторая кнопка, Publish to GitHub, дополнительно создаёт репозиторий на GitHub. Её используют, когда проект с начала общий. В проектах этого курса историю сначала заводят у себя, публикация разобрана в модуле 4.

На полях: откуда имя main

Имя первой ветки задаёт Git. До 2020 года по умолчанию использовалось master, затем GitHub и Git перешли на main, поэтому в старых проектах встречается прежнее имя. Имя задаётся настройкой из главы 1.3: git config --global init.defaultBranch main.

Что получилось.В папке заведён пустой репозиторий, внизу окна имя main.

§3Путь А, шаг 2. Проверить, что появилось на диске

Шаг показывает, что появилось в папке после Initialize Repository.

В проводнике папка выглядит как прежде. В ней появилась скрытая папка .git, её показывает команда вывода скрытых файлов. Команды набираются во встроенном терминале VS Code: меню Terminal → New Terminal или Ctrl + `. Терминал открывается внизу окна сразу в папке проекта.

В Windows терминал по умолчанию — PowerShell, и в нём эта команда пишется ls -Force. Ответ выглядит как таблица, но папка .git в ней та же.Команда ls -a выводит все файлы папки, включая скрытые:

Точка и две точки — сама папка и родительская, они есть в любой папке. Третья строка — новая папка .git. Её содержимое:

Содержимое .git сразу после Initialize Repository

.git/весь репозиторий: при удалении этой папки история пропадёт, файлы останутся
  ├── HEADна какой ветке вы сейчас
  ├── configнастройки этого репозитория, в том числе адрес сервера
  ├── descriptionописание, нужное старым серверам; обычно не трогают
  ├── hooks/заготовки скриптов, которые можно запускать при коммите
  ├── info/служебные настройки
  ├── objects/здесь будут лежать сохранённые состояния файлов — пока пусто
  └── refs/ветки: в каждом файле имя одного коммита — тоже пусто

Содержимое разбирается в модуле 3. История проекта хранится в этой папке на вашем компьютере и копируется вместе с папкой проекта.

Состояние нового репозитория по команде git status:

Git сообщает три вещи: ветка называется main, коммитов нет, файлов для отслеживания нет. То же показывает пустая панель Source Control. Путь А закончен.

Что получилось.В папке есть скрытая .git. Git подтверждает: коммитов нет, отслеживать нечего.

§8Путь Б, шаг 5. Убедиться, что пришла история

Вместе с файлами скачиваются все прошлые версии. Это проверяют двумя командами в терминале проекта.

Каждая строка — коммит, самый ранний внизу. Слева короткое имя коммита, справа пояснение автора. Коммиты хранятся на диске и открываются без интернета. По ним видно, что сайт начался с одной страницы, затем подключили стили, добавили абзац и описание.

Адрес сервера записан под коротким именем origin. Поэтому в строке состояния появились стрелки обмена. Строки две, потому что адрес получения и адрес отправки можно задать разными; обычно они совпадают.

После Initialize RepositoryКоммитов нет, удалённой копии нет, ветка main создана, но пустая
↔
После CloneВся история на диске, адрес origin прописан, ветка main стоит на последнем коммите

Ассоциация: два способа получить тетрадь

Завести свою

Чистую тетрадь начинают с первой страницы. Каждую новую запись датируют и подписывают.

Взять копию чужой

Точная копия чужой тетради содержит все прошлые записи с датами и подписями авторов. В ней можно читать прошлые записи и добавлять новые в конец.

Где не совпадаетКопия тетради не связана с оригиналом. В клоне записан адрес репозитория, из которого он скачан: с него получают новые коммиты и на него отправляют свои. Обмен запускают кнопкой, он разобран в модуле 4.

На полях: сколько весит история

Скачиваются текущая версия файлов и все прошлые состояния. У проекта sait-vizitka из трёх файлов папка .git занимает около 120 КБ, больше самих файлов. У проектов с долгой историей она может быть в несколько раз больше рабочих файлов.

Что получилось.Вместе с файлами пришли все четыре коммита и адрес сервера origin.

3Справка

§9Clone или Download ZIP

В меню кнопки Code есть пункт Download ZIP. Он скачивает только файлы последней версии.

Download ZIP

Архив с файлами последней версии.

  • Истории нет: в архиве нет папки .git
  • Вернуться к прошлой версии нельзя
  • Отправить правки автору нельзя
  • Для обновления архив скачивают заново

Clone

Полноценный репозиторий на вашем диске.

  • Все версии и ветки доступны на диске
  • Обновление — одной кнопкой, без повторного скачивания
  • Свои правки можно предложить автору
  • Панель Source Control работает

Архив скачивают, когда нужен разовый образец: шаблон, пример вёрстки, набор картинок. Для работы с проектом его клонируют. Архив не обновляется и не хранит адрес, откуда он скачан.

§10Где можно ошибиться

Ниже частые ошибки при создании и клонировании репозитория. О каждой Git сообщает в ответе команды.

Репозиторий внутри репозитория

Если в подпапке уже существующего репозитория нажать Initialize Repository, получатся два вложенных репозитория. Внешний перестаёт отслеживать файлы подпапки, внутренний ведёт отдельную историю.

Git это разрешает, вложенные репозитории иногда создают намеренно. В работах этого курса это ошибка, её исправляют удалением лишней папки .git из подпапки. Признак в панели: файлы подпапки не появляются в списке изменений.

init поверх готового репозитория

Повторный запуск в той же папке историю не стирает:

Ответ отличается словом Reinitialized вместо Initialized. Коммиты сохраняются.

Клонирование в непустую папку

Если папка с таким именем уже существует и не пуста, клонирование не выполняется:

Git не перезаписывает существующие файлы. Нужно выбрать другое место или указать другое имя папки последним аргументом команды.

Репозиторий в облачной папке

Репозиторий в синхронизируемой папке — iCloud Drive, Google Drive, OneDrive — может повредиться. Облачный клиент копирует служебные файлы .git независимо от Git, а при работе с двух компьютеров файлы истории меняются одновременно. Между компьютерами проект синхронизируют через GitHub.

Проверка после создания или клонирования

Внизу окна видно имя веткиНапример, main. Если имени нет — репозитория в этой папке нет.
Открыта папка проектаВ проводнике VS Code верхняя строка — имя вашего проекта. Если там Documents или имя пользователя, открыта папка уровнем выше.
Панель Source Control работаетНовый файл появляется в списке Changes.
Для клона: история на местеgit log --oneline показывает чужие коммиты, а в строке состояния стоят стрелки обмена.

4Проверка себя

§12Частые вопросы

Обычно думаютКлонировать можно только свои проекты.
На самом делеЛюбой открытый репозиторий клонируется без регистрации и разрешения автора. Отправлять правки в чужой проект напрямую нельзя, для этого используют форки и pull request (модуль 5).
Обычно думаютInitialize Repository сразу создаёт проект на GitHub.
На самом делеСоздаётся только папка .git на вашем компьютере. На GitHub проект появляется после Publish to GitHub или настройки отправки.
Обычно думаютКлон — то же, что скопированная папка.
На самом делеСкопированная папка сохраняет историю, если в ней есть .git. В клоне дополнительно записан адрес сервера origin, через который идёт обмен коммитами.
Обычно думаютЕсли удалить папку .git, проект сломается.
На самом делеФайлы останутся, пропадёт история: прошлые версии, авторы и пояснения. Без копии на сервере историю не восстановить.

§13Проверьте себя

Вам прислали ссылку на проект. Как начать с ним работать?

Открыть страницу проекта, нажать Code и скопировать адрес из поля HTTPS. В VS Code открыть палитру команд, выбрать Git: Clone, вставить адрес, выбрать папку и открыть проект. В папке будут файлы, вся история и адрес origin.

Чем состояние папки после Initialize Repository отличается от состояния после клонирования?

После init история пустая: ветка main создана, коммитов ноль, удалённой копии нет, внизу окна значок облака. После клонирования на диске лежат все коммиты проекта, ветка стоит на последнем из них, адрес записан под именем origin, а внизу окна стрелки обмена.

Почему проект, который будете дорабатывать, не скачивают через Download ZIP?

В архиве нет папки .git, а значит, нет истории: прошлых версий, авторов строк, возможности отмены. Обновление — только повторное скачивание архива. Отправить правки автору из архива нельзя.

В ответ на команду Git написал Reinitialized existing Git repository. Что произошло и опасно ли это?

Репозиторий в этой папке уже существовал, команда запущена повторно. Коммиты, ветки и настройки сохранились. Слово Reinitialized означает, что папка .git не создавалась заново.

Проект лежит в папке Google Drive, и Git сообщает об ошибках в репозитории. В чём причина?

Облачный клиент копирует служебные файлы .git независимо от Git, а при работе с двух компьютеров — одновременно с обеих сторон. От этого репозиторий повреждается. Проект синхронизируют через GitHub: на каждом компьютере свой клон, изменения передаются коммитами.

Что такое origin?

Короткое имя адреса удалённой копии проекта. Оно заменяет длинную ссылку в командах. При клонировании Git создаёт его автоматически, адрес показывает команда git remote -v.

§14Шпаргалка по главе

Путь А: свой проект File → Open Folder Initialize Repository git init
Путь Б: чужой проект кнопка Code → HTTPS → копировать палитра: Git: Clone git clone адрес
Что создаётся .git — история проекта ветка main origin — только у клона
Проверить git status — состояние git log --oneline — история git remote -v — адрес сервера
Не делать init в домашней папке init внутри чужого репозитория репозиторий в облачной папке
ZIP против клона ZIP — файлы без истории клон — файлы и вся история

Итог главы

Путь А: открыть папку, нажать Initialize Repository — появляется .git и ветка main, история пустая, сервер не задействован. Путь Б: скопировать адрес под кнопкой Code, вызвать Git: Clone, вставить адрес, выбрать папку — на диске оказывается проект со всеми коммитами и записанным адресом origin. Архив ZIP содержит только файлы без истории, поэтому для работы с проектом его не используют. Репозиторий заводят в папке конкретного проекта: вне домашней папки, вне другого репозитория и вне облачной папки. В следующей главе разобрано, что происходит между правкой файла и коммитом и зачем нужен отбор изменений.
