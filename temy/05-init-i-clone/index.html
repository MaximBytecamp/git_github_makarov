§1Две ситуации, других не бывает

Работа над проектом начинается либо с пустой папки, либо с чужого готового кода. Git на это отвечает двумя разными действиями, и путать их нельзя: одно создаёт историю, второе скачивает существующую.

Проект начинаете вы

Initialize Repository — заводит историю прямо в вашей папке. Файлы остаются на месте, рядом появляется .git.

  • История пустая: коммитов ноль
  • Интернет не нужен
  • На GitHub ничего пока нет

Проект уже существует

Clone Repository — скачивает проект целиком: файлы, все коммиты, все ветки и адрес сервера, откуда всё взято.

  • История приходит вместе с файлами
  • Нужен интернет и адрес репозитория
  • Связь с сервером настроена сразу

Зачем это нужно в работе

  • Приход на готовый проект. Первое, что делают на новом месте, — клонируют репозиторий команды. Скачанная папка сразу знает, куда отправлять правки.
  • Своя разработка с первого дня. Репозиторий заводят не в конце, когда «уже есть что сохранять», а сразу: иначе первые дни работы останутся без истории.
  • Чужой код для изучения. Клонирование даёт не только текущие файлы, но и переписку изменений: видно, как проект пришёл к нынешнему виду.
  • Копия на другом компьютере. Тот же проект дома и на работе — это два клона одного репозитория, а не две папки, которые вы переносите флешкой.

§2Четыре слова, которые дальше встречаются постоянно

Эти четыре понятия будут в каждой следующей главе. Их стоит развести сразу.

initзавести историю в своей папке

Кнопка Initialize Repository в панели Source Control. Создаёт в папке скрытый каталог .git и с этого момента начинает следить за изменениями. Файлы не трогаются: что лежало, то и лежит.

То же самое командой: git init. Ответ Git — одна строка:

cloneзабрать чужой репозиторий себе

Создаёт на вашем диске новую папку и складывает в неё файлы проекта вместе со всей историей. Клон — полноценный репозиторий, а не снимок: в нём доступны все прошлые версии, даже без интернета.

Командой: git clone https://github.com/MaximBytecamp/git_github_makarov.git

remoteкопия проекта на сервере

Адрес удалённой копии, с которой ваша папка обменивается коммитами. Репозиторий может обходиться без него: работа на одном компьютере удалённой копии не требует.

originимя основной удалённой копии

Не команда и не место — просто короткое имя адреса, чтобы не писать длинную ссылку каждый раз. При клонировании Git присваивает его сам. Увидеть, что за ним стоит, можно так:

Две строки вместо одной — потому что адрес получения и адрес отправки разрешено делать разными. В обычном проекте они совпадают.

На полях: почему интерфейс нарисован

Панель VS Code в этой главе перерисована, а не снята. Так каждый шаг показан на одном и том же учебном проекте, без посторонних файлов: у вас на экране будет то же самое. Кадры GitHub — настоящие.

Точка и две точки — это сама папка и родительская, они есть везде. Третья строка — новая. Внутри неё:

Содержимое .git сразу после Initialize Repository

.git/весь репозиторий: удалите эту папку — исчезнет история, файлы останутся
  ├── HEADна какой ветке вы сейчас
  ├── configнастройки этого репозитория, в том числе адрес сервера

Разбирать содержимое сейчас не нужно. Важно одно: история проекта лежит здесь, а не на сайте и не в редакторе. Скопируете папку проекта на флешку — история поедет вместе с ней.

§5Откуда взялась ветка main

Имя первой ветки никто не выбирал: его подставил Git. До 2020 года везде по умолчанию стояло master, затем GitHub и вслед за ним Git перешли на main. Поэтому в старых проектах и статьях встречается прежнее имя — это та же самая основная ветка.

Имя по умолчанию задаётся настройкой, которую мы выставляли при установке в главе 1.3:

Если её не выставить, Git при каждом init напоминает об этом длинным предупреждением. Настройка снимает предупреждение и делает имя ветки одинаковым во всех новых проектах.

§6Путь Б: где взять адрес чужого проекта

Для клонирования нужен адрес репозитория. Он не берётся из адресной строки браузера — там ссылка на страницу. Настоящий адрес лежит под зелёной кнопкой Code на странице проекта.

Адрес заканчивается на .git — так выглядит ссылка именно на репозиторий:

Ссылка на страницуhttps://github.com/MaximBytecamp/git_github_makarov
→
Адрес репозиторияhttps://github.com/MaximBytecamp/git_github_makarov.git

Отличается одним окончанием. Git принимает и ссылку без .git — сам достроит, — но копировать надёжнее из того поля, где адрес дан целиком.

§7Клонирование в VS Code по шагам

  1. Скопируйте адрес кнопкой копирования справа от поля.
  2. В VS Code откройте палитру команд: CtrlCmd + Shift + P, наберите Git: Clone и выберите этот пункт. То же самое делает кнопка Clone Repository на стартовом экране пустого окна.
  3. Вставьте адрес в появившееся поле и нажмите Enter.
  4. Выберите папку, в которой появится проект. Именно в которой: сама папка проекта создастся внутри с именем репозитория. Отдельную папку заранее делать не нужно.
  5. Дождитесь окончания загрузки и в появившемся вопросе нажмите Open.

В терминале то же действие — одна строка, и Git отвечает коротко:

Ассоциация: два способа получить тетрадь

Завести свою

Вы берёте чистую тетрадь и начинаете писать с первой страницы. В ней пока ничего нет, но дальше каждая запись будет датирована и подписана вами. Никто, кроме вас, о ней не знает.

Взять копию чужой

Вам отдают точную копию чужой тетради: все прошлые записи на месте, вместе с датами и почерком авторов. Вы можете листать её назад и дописывать своё в конец.

Где не совпадаетКопия тетради живёт отдельно от оригинала, а клон помнит адрес, откуда взят: он умеет забирать чужие новые записи и отправлять ваши обратно. Обмен не происходит сам — его запускают кнопкой, и об этом модуль 4.

Связь с сервером настроена — адрес записан под именем origin:

↔
После CloneВся история на диске, адрес origin прописан, ветка main стоит на последнем коммите
На полях: история весит место

Скачивается не только текущая версия файлов. Папка .git этого справочника занимает около 3 МБ при небольшом размере самих файлов — в ней лежат все прошлые состояния. У больших проектов история бывает в разы тяжелее рабочих файлов, и это нормально.

§9Clone или Download ZIP

В том же меню под кнопкой Code есть пункт Download ZIP. Он скачивает файлы — и только их.

Download ZIP

Архив с файлами последней версии.

  • Истории нет — папки .git в архиве не будет
  • Вернуться к прошлой версии нельзя
  • Отправить правки автору нельзя
  • Обновить до новой версии — только скачать архив заново

Clone

Полноценный репозиторий на вашем диске.

  • Все версии и ветки доступны сразу
  • Обновление — одна кнопка, а не повторное скачивание
  • Свои правки можно предложить автору
  • Панель Source Control работает

Архив уместен, когда нужен разовый образец — шаблон, пример вёрстки, набор картинок. Во всех остальных случаях клонируют: скачанный ZIP через неделю превращается в устаревшую папку, о происхождении которой никто не помнит.

§10Где можно ошибиться

Четыре ситуации, которые случаются на первой неделе. Все четыре Git показывает явно — надо только прочитать сообщение.

Репозиторий внутри репозитория

Вы клонировали проект, зашли в его папку и по привычке нажали Initialize Repository в подпапке. Получились две истории, вложенные друг в друга: внешняя видит подпапку как один непонятный объект, внутренняя живёт сама по себе.

Git не возражает — такое бывает нужно, — но в учебной работе это всегда ошибка. Лечится удалением лишней папки .git из подпапки. Признак в панели: файлы подпапки перестают появляться в списке изменений.

Репозиторий в облачной папке

Проект, заведённый внутри синхронизируемой папки — iCloud Drive, Google Drive, OneDrive, — рано или поздно ломается. Облако синхронизирует служебные файлы .git по своим правилам и в свой момент; два компьютера, пишущие в одну историю одновременно, приводят к повреждению репозитория. Для синхронизации между машинами используется сам GitHub — он для этого и сделан.

§11Частые вопросы

Обычно думаютКлонировать можно только свои проекты.
На самом делеЛюбой открытый репозиторий клонируется без регистрации и без разрешения автора. Ограничение начинается при отправке правок: писать в чужой проект напрямую нельзя, для этого есть форки и pull request — модуль 5.
Обычно думаютInitialize Repository сразу создаёт проект на GitHub.
На самом делеСоздаёт только папку .git на вашем компьютере. На сайте ничего не появится, пока не нажата Publish to GitHub или не настроена отправка.
Обычно думаютКлон — это копия папки, как через «скопировать — вставить».
На самом делеКопия папки тоже сохраняет историю, но не знает про сервер и живёт отдельно. Клон помнит адрес origin и умеет обмениваться коммитами.
Обычно думаютЕсли удалить папку .git, проект сломается.
На самом делеФайлы останутся целыми — исчезнет история: все прошлые версии, авторы и пояснения. Обратно это не восстанавливается, если нет копии на сервере.

§12Проверьте себя

Вам дали ссылку на проект в чате. Что вы сделаете, чтобы начать работать?

Открою страницу проекта, нажму Code, скопирую адрес из поля HTTPS. В VS Code — палитра команд, Git: Clone, вставить адрес, выбрать папку, в которой появится проект, и открыть его. После этого в папке есть файлы, вся история и настроенный origin.

Чем состояние папки после Initialize Repository отличается от состояния после клонирования?

После init история пустая: ветка main создана, коммитов ноль, удалённой копии нет. После клонирования на диске лежат все коммиты проекта, ветка стоит на последнем из них, а адрес сервера записан под именем origin.

Почему не стоит скачивать проект через Download ZIP, если планируете его дорабатывать?

В архиве нет папки .git, а значит нет истории: нельзя посмотреть прошлые версии, откатиться, увидеть автора строки. Нельзя и обновиться — только скачать архив заново и вручную разобраться, что изменилось. Отправить свои правки автору тоже не получится.

В ответ на команду Git написал Reinitialized existing Git repository. Что произошло и опасно ли это?

Репозиторий в этой папке уже был, и вы завели его повторно. Не опасно: коммиты, ветки и настройки остались на месте. Слово Reinitialized — просто уведомление, что папка .git не создавалась заново.

Коллега держит проект в папке Google Drive и жалуется, что Git «сходит с ума». В чём причина?

Облако синхронизирует служебные файлы .git само по себе и в неподходящий момент, а при работе с двух компьютеров — ещё и одновременно. Репозиторий от этого повреждается. Синхронизировать проект между машинами нужно через GitHub: клон на каждом компьютере плюс обмен коммитами.

Что такое origin своими словами?

Короткое имя для адреса удалённой копии проекта. Не папка и не команда — просто закладка, чтобы не писать длинную ссылку каждый раз. При клонировании Git создаёт её сам, посмотреть адрес можно командой git remote -v.

Итог главы

Репозиторий заводят одним из двух способов. Initialize Repository создаёт историю в вашей папке: появляется .git и ветка main, коммитов пока нет, сервер не задействован. Clone скачивает готовый проект вместе со всеми коммитами и записывает адрес источника под именем origin. Архив ZIP выглядит похоже, но истории не содержит, поэтому для работы не годится. Заводить репозиторий нужно в папке конкретного проекта — не в домашней, не внутри другого репозитория и не в облачной. В следующей главе разберём, что происходит между правкой файла и коммитом: зачем вообще нужен второй шаг с отбором изменений.
