§1Рабочая папка, индекс, история

Правка попадает в историю в два шага и по пути проходит три места: рабочую папку, индекс и историю.

Индекс — среднее место, куда складывают то, что войдёт в следующий коммит. В панели VS Code он называется Staged Changes, в командах Git — index или staging area. Пока коммит не сделан, содержимое индекса можно менять.

Зачем это нужно в работе

  • Отдельный коммит на каждую задачу. За один сеанс работы обычно меняются вёрстка, текст и настройки. Если записать всё одним коммитом, отменить одну из этих правок отдельно не получится.
  • Готовое сохраняется отдельно от незаконченного. Законченную правку отбирают и коммитят, незаконченная остаётся в папке.
  • Проверка перед коммитом. Индекс показывает, что войдёт в коммит. На этом этапе видно случайно отобранный файл с паролем или отладочную строку.
  • Понятная история для команды. По списку коммитов коллеги узнают, что менялось в проекте. Сообщение «Добавил страницу контактов» это сообщает, сообщения «правки» и «фикс» — нет.

Ассоциация: две коробки для переезда

В жизни

При переезде посуду и книги складывают в разные коробки и каждую подписывают. На новом месте нужную коробку находят по подписи.

В Git

Плюс у файла кладёт его в коробку — индекс. Commit заклеивает коробку и подписывает её сообщением. Следующие правки складываются уже в новую коробку.

Где не совпадаетКоробка в Git одна: пока первая не заклеена, вторую собрать нельзя. Поэтому коммиты делают по очереди.

§6Шаг 4. Написать сообщение из двух частей

Щёлкаем в поле Message и пишем первую строку — короткий заголовок: «Добавил страницу контактов». Дважды нажимаем Shift + Enter и пишем пояснение: «Новая страница kontakty.html и ссылка на неё с главной.»

На полях: почему Shift + Enter

CtrlCmd + Enter в этом поле сразу создаёт коммит. Shift + Enter только переводит строку, поэтому коммит не создастся до того, как дописано пояснение.

Что получилось.В поле Message заголовок и пояснение, разделённые пустой строкой.

Первая M — изменение в индексе, вторая — изменение в папке, не отобранное в индекс. Коммит, сделанный сейчас, включил бы только новый отступ, а блок footer остался бы в Changes.

Сообщение коммита читают при поиске нужного изменения в истории. Первая строка сообщает, что изменилось в проекте.

Проверка сообщения перед коммитом

Первая строка короткаяДо 50–70 символов: такая строка целиком видна в списках истории и на GitHub.
Сказано, что сделаноПеречислять тронутые файлы не нужно: Git хранит их список сам, его видно командой git log --stat.
Одна задача в одном коммитеЕсли в сообщении есть союз «и», проверьте, не две ли это задачи.
Пояснение отдельным абзацемПосле пустой строки пишут причину изменения, если она не видна из кода.
5Проверка себя

§12Частые вопросы

Обычно думаютИндекс — лишний шаг.
На самом делеВ индексе собирается будущий коммит. Без индекса в коммит попадали бы все изменения папки сразу.
Обычно думаютЕсли файл в Staged Changes, его больше нельзя править.
На самом делеПравить можно. Новые правки появятся в Changes, а в индексе останется отобранное состояние. Файл будет в обоих разделах.
Обычно думаютЧастые коммиты засоряют историю.
На самом делеИсторию засоряют коммиты без ясного сообщения. Коммит на каждую законченную задачу — обычная практика: по небольшим коммитам проще найти и отменить ошибку.
Обычно думаютКнопка «плюс» сохраняет файл.
На самом делеФайл сохраняет редактор по CtrlCmd + S. Плюс отбирает сохранённое состояние в индекс, в историю его записывает Commit.

§13Проверьте себя

В панели три файла в Changes и ноль в Staged Changes. Что произойдёт по нажатию Commit?

Индекс пуст, поэтому VS Code предложит отобрать все изменения сразу. Если согласиться, в коммит войдут все три файла. Порядок работы: плюс у нужных файлов, сообщение, Commit.

Один и тот же файл оказался и в Staged Changes, и в Changes. Как это возможно?

В индекс отобрана часть правок файла, например один участок кнопкой Stage Block. Остальные правки остались в рабочей папке. В коммит войдёт только отобранное. git status --short показывает такой файл буквами MM.

Вы отобрали файл в индекс, а потом передумали. Как вернуть, не потеряв правки?

Навести курсор на файл в Staged Changes и нажать − (Unstage Changes). Файл вернётся в Changes, текст не изменится. Круговая стрелка рядом стирает правки.

За утро вы поправили вёрстку шапки, исправили опечатку в тексте и добавили новую картинку. Сколько коммитов делать?

Три, по числу задач. Тогда вёрстку шапки можно будет отменить отдельно. При одном общем коммите отмена затронет и опечатку, и картинку.

Чем git diff отличается от git diff --staged?

Первая показывает правки, не отобранные в индекс, — раздел Changes. Вторая показывает содержимое индекса — раздел Staged Changes, то есть следующий коммит.

Почему в сообщении коммита первую строку делают короткой?

Первую строку показывают списки истории: раздел Graph, вывод git log --oneline, страница коммитов на GitHub. Длинная строка в них обрезается. Подробности пишут после пустой строки.

Итог главы

Между рабочей папкой и историей находится индекс — раздел Staged Changes. Плюс отбирает правки в индекс, Commit записывает содержимое индекса в историю. Индекс позволяет разделить правки по задачам: в главе четыре правки записаны двумя коммитами. Отбирают файл целиком, все файлы списка или отдельный участок файла; в последнем случае файл находится в обоих разделах. Сообщение коммита состоит из короткого заголовка и пояснения после пустой строки. В следующей главе разобрано, как читать историю, искать нужный коммит и узнавать автора строки.
