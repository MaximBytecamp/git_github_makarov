Git и GitHub:
кто что делает

Эти два названия постоянно употребляют как одно. Git — программа на вашем компьютере, GitHub — сайт, на котором хранят копию репозитория. Разберём, что делает каждый, что будет работать без интернета и почему GitHub можно заменить другим сервисом или не использовать вовсе.

§1Откуда берётся путаница

Студент говорит: «я залил работу на гит», «скачай с гита», «у меня гит не открывается». Во всех трёх фразах речь про сайт GitHub, а слово сказано про программу Git. Путаница живучая, и причина простая: у большинства знакомство начинается с сайта. Человек регистрируется на GitHub, нажимает зелёную кнопку, получает ссылку — и всё это время считает, что пользуется Git.

Разница видна, как только что-то ломается. Пропал интернет — работать с Git можно, а с GitHub нельзя. Удалили репозиторий на сайте — история на диске осталась. Не вошли в аккаунт — коммиты всё равно создаются. Чтобы такие ситуации не удивляли, разберём обе стороны по отдельности.

§2Git: программа на вашем компьютере

Git устанавливается как обычная программа и запускается локально. Он следит за одной папкой — той, в которой вы создали репозиторий, — и хранит её историю в скрытом каталоге .git внутри этой же папки.

Вот что Git делает целиком у вас на диске:

  • записывает коммиты — сохранённые состояния проекта с автором, датой и пояснением;
  • показывает, какие строки изменились с прошлого коммита;
  • создаёт ветки и объединяет их, в том числе с разбором конфликтов;
  • возвращает файлы к любому сохранённому состоянию;
  • ищет, в каком коммите появилась конкретная строка.

Для всего перечисленного не нужны ни интернет, ни аккаунт, ни регистрация. Git не знает, что такое GitHub: для него это просто адрес, по которому лежит ещё одна копия репозитория.

На полях: где именно лежит история

Откройте папку проекта и включите показ скрытых файлов — увидите каталог .git. В нём и хранятся все коммиты. Скопируете папку проекта на флешку вместе с .git — перенесёте и всю историю. Удалите .git — останутся только текущие файлы, без единой прошлой версии.

§3GitHub: сайт с копией репозитория

GitHub — веб-сервис, принадлежащий Microsoft. Его основная работа — хранить копию вашего репозитория на своих серверах и отдавать её по запросу. Всё остальное надстроено вокруг этой копии и к самому Git отношения не имеет.

Что добавляет сервис:

  • страницу проекта, где код виден в браузере, без установки чего-либо;
  • задачи (Issues) с метками, исполнителями и обсуждением;
  • pull request — предложение внести изменения, с ревью и замечаниями к конкретным строкам;
  • права доступа: кто может читать, кто писать, кто менять настройки;
  • канбан-доски в Projects, автоматические проверки в Actions, публикацию сайта через Pages.

Ни одной из этих возможностей в Git нет. Pull request, метки и доски придуманы сервисом; Git о них не знает и работает точно так же, если вы ими не пользуетесь.

Строка «отправить коммиты» отмечена в обеих колонках: команду выполняет Git, а принимает и сохраняет их сервис. Это единственное место, где они работают вместе, — и именно поэтому его разберём подробнее.

§5Как они соединяются

Связь между вашим компьютером и сервисом устроена просто. В настройках репозитория Git хранит список удалённых репозиториев — это адреса копий, с которыми вы обмениваетесь коммитами. У первого такого адреса принято имя origin; никакого особого смысла в нём нет, это просто короткое имя, чтобы не писать ссылку целиком.

Важное следствие: пока вы не нажали Sync, на GitHub ничего нового нет. Работа, сделанная за вечер, лежит только на вашем диске — и если диск откажет, восстанавливать будет нечего. Отправка коммитов и есть тот момент, когда сервис начинает что-то знать о вашем проекте.

§6Что работает без интернета

Проверить своё понимание разницы проще всего одним вопросом: что останется работать, если выдернуть сетевой кабель.

СитуацияРаботаетНет
Сделать коммит в поезде без связи
Посмотреть историю за прошлый месяц
Создать ветку и переключиться на неё

Отсюда привычка, которая экономит нервы: коммиты делать по ходу работы, а отправку — когда появится сеть. Git для этого и создавался: разработчики ядра Linux работали в самолётах и поездах задолго до повсеместного интернета.

§7Откуда взялся GitHub

Git появился в 2005 году, а сервис вокруг него — через три года. Идея была в том, что публиковать репозиторий на своём сервере умеют не все, а показать проект и принять правку хочется каждому.

2008запуск
GitHub открывается для всех

Крис Ванстрат, Том Престон-Вернер и Пи Джей Хайетт делают сайт, где репозиторий Git размещается за пару кликов. Главное изобретение сервиса — pull request: механизм предложить чужому проекту свою правку и обсудить её.

2008Pages
Сайт прямо из репозитория

Появляется GitHub Pages: страницы проекта публикуются из той же ветки, где лежит код. Этим справочником вы пользуетесь именно так.

2018Microsoft
Покупка за 7,5 млрд долларов

Microsoft покупает GitHub. Руководителем становится Нат Фридман. Бесплатные приватные репозитории, которые раньше стоили денег, открывают для всех.

2019Actions
Автоматические проверки

GitHub Actions запускает сборку и тесты при каждом изменении. Отдельный сервер для этого больше не нужен — разберём в седьмом модуле.

2023масштаб
Больше 100 миллионов пользователей

По данным самого сервиса, на нём зарегистрировано свыше ста миллионов разработчиков. Это делает GitHub самой заметной, но не единственной площадкой.

Для нас из этой истории важно одно: GitHub — коммерческий продукт конкретной компании. Он может менять правила, тарифы и внешний вид, и это никак не затрагивает Git. Репозиторий, который лежит у вас на диске, от решений Microsoft не зависит.

§8Сервисов много, Git один

GitHub — не единственное место, куда можно положить репозиторий. Все перечисленные сервисы работают с тем же самым Git: команды одинаковые, меняется только адрес.

GitHub · Microsoft
GitLab · можно свой сервер
Bitbucket · Atlassian
Gitea · лёгкий, свой
Codeberg · некоммерческий

Логотипы: GitHub — MIT; GitLab — MIT; Bitbucket — Atlassian, общественное достояние; Gitea — MIT; Codeberg — CC0. Источник — Wikimedia Commons.

Больше того, сервис не обязателен вовсе. Общей копией может быть папка на сетевом диске, репозиторий на арендованном сервере или флешка: Git умеет обмениваться коммитами и так. Поэтому правильная формулировка — «репозиторий размещён на GitHub», а не «проект написан на GitHub».

На полях: почему в учёбе всё-таки GitHub

На нём лежит большинство открытых проектов, он бесплатен для учебных задач, поддерживается Visual Studio Code без настройки и даёт всё, что нужно курсу: задачи, pull request, доски и публикацию сайта. Переход на другой сервис после этого занимает один вечер — команды те же.

§9Разбор привычных фраз

Эти фразы вы услышите и на парах, и на работе. Разберём, что в них имеется в виду и как сказать точнее.

«Залил работу на гит»

Что произошлоКоммиты отправлены командой Git в копию репозитория на GitHub. Точнее: «отправил коммиты на GitHub» или «сделал push».

«Скачай проект с гита»

Что произошлоРечь про клонирование репозитория с GitHub. Точнее: «склонируй репозиторий с GitHub».

«У меня гит не открывается»

Что произошлоНе открывается сайт: пропал интернет или лежит сервис. Git на компьютере при этом работает, коммиты делать можно.

«Сохрани на гитхаб, чтобы не потерялось»

Что произошлоСначала нужен коммит — иначе отправлять нечего. Порядок такой: сохранить файлы, сделать коммит, нажать Sync.

§10Частые заблуждения

Обычно думаютБез аккаунта на GitHub пользоваться Git нельзя.
На самом делеGit ставится и работает без всякой регистрации. Аккаунт нужен только для того, чтобы хранить копию на сервисе и работать вместе с другими.
Обычно думаютУдалил репозиторий на GitHub — потерял проект.
На самом делеПолная копия истории осталась на вашем диске, в папке .git. Проект можно разместить заново — хоть на GitHub, хоть в другом месте.
Обычно думаютPull request — это возможность Git.
На самом делеPull request придуман сервисами. В Git есть ветки и слияние, а обсуждение правки с ревью и кнопкой «влить» добавляет GitHub.
Обычно думаютФайлы на сайте и файлы на компьютере — это одно и то же.
На самом делеЭто две копии. Они совпадают только после отправки и получения изменений; между этими действиями расходятся.

§11Проверьте себя

Интернет пропал на весь день. Что из работы с репозиторием останется доступным?

Всё, кроме обмена с сервисом: коммиты, просмотр истории, ветки, слияния, откаты к прошлым состояниям. Не сработают отправка коммитов, получение чужих изменений, клонирование нового проекта и любые действия на сайте — задачи, pull request, доски.

Что такое origin?

Имя удалённого репозитория — короткая замена его адресу. По традиции так называют первую удалённую копию, обычно ту, что на GitHub. Имя можно поменять, и удалённых копий может быть несколько.

Вы весь вечер делали коммиты, но не нажимали Sync. Что видит преподаватель на GitHub?

Состояние на момент последней отправки. Коммиты вечера лежат только на вашем компьютере: пока не выполнен push, сервис о них не знает.

Чем pull request отличается от слияния веток в Git?

Слияние — операция Git: она объединяет две ветки на вашем компьютере. Pull request — страница на сервисе, где предложенное изменение обсуждают, просматривают построчно и одобряют, а слияние выполняется уже после этого. Без сервиса можно слить ветки, но нельзя обсудить правку в таком виде.

Одногруппник говорит: «перенеси проект с гитхаба на гитлаб — придётся всё переделывать». Он прав?

Нет. Оба сервиса работают с одним и тем же Git: нужно добавить второй адрес удалённого репозитория и отправить туда коммиты. Переносить придётся не код, а то, что принадлежит сервису: задачи, доски, настройки доступа.

Объясните своими словами, почему фраза «программа написана на GitHub» неверна.

GitHub — место хранения репозитория и площадка для совместной работы, а не язык и не среда разработки. Программа написана на каком-то языке, в каком-то редакторе, а её история хранится в Git; GitHub держит копию этой истории и даёт к ней доступ другим людям.

§12Шпаргалка по главе

Git программа на компьютере коммиты, ветки, история работает без сети
GitHub сайт с копией репозитория задачи, PR, доски, Pages нужен интернет и аккаунт
Связь между ними origin — имя удалённой копии push — отправить коммиты pull — забрать чужие
Как говорить точно не «залил на гит» а «отправил на GitHub»

Итог главы

Git и GitHub — разные вещи с похожими названиями. Git хранит историю проекта на вашем диске и выполняет все операции с ней локально. GitHub хранит копию этой истории на своих серверах и добавляет то, чего в Git нет: задачи, pull request, права доступа, доски и публикацию сайта. Соединяет их список удалённых репозиториев: push отправляет коммиты в копию, pull забирает чужие. Сервис при этом заменим, а Git — общая основа для всех таких площадок. Следующая глава — о том, как именно Git хранит историю внутри папки .git.
