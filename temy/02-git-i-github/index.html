кто что делает

§1Откуда берётся путаница

Студент говорит: «я залил работу на гит», «скачай с гита», «у меня гит не открывается». Во всех трёх фразах речь про сайт GitHub, а слово сказано про программу Git. Путаница живучая, и причина простая: у большинства знакомство начинается с сайта. Человек регистрируется на GitHub, нажимает зелёную кнопку, получает ссылку — и всё это время считает, что пользуется Git.

Разница видна, как только что-то ломается. Пропал интернет — работать с Git можно, а с GitHub нельзя. Удалили репозиторий на сайте — история на диске осталась. Не вошли в аккаунт — коммиты всё равно создаются. Чтобы такие ситуации не удивляли, разберём обе стороны по отдельности.

§2Git: программа на вашем компьютере

Git устанавливается как обычная программа и запускается локально. Он следит за одной папкой — той, в которой вы создали репозиторий, — и хранит её историю в скрытом каталоге .git внутри этой же папки.

Вот что Git делает целиком у вас на диске:

  • записывает коммиты — сохранённые состояния проекта с автором, датой и пояснением;
  • показывает, какие строки изменились с прошлого коммита;
  • создаёт ветки и объединяет их, в том числе с разбором конфликтов;
  • возвращает файлы к любому сохранённому состоянию;
  • ищет, в каком коммите появилась конкретная строка.

Для всего перечисленного не нужны ни интернет, ни аккаунт, ни регистрация. Git не знает, что такое GitHub: для него это просто адрес, по которому лежит ещё одна копия репозитория.

На полях: где именно лежит история

Откройте папку проекта и включите показ скрытых файлов — увидите каталог .git. В нём и хранятся все коммиты. Скопируете папку проекта на флешку вместе с .git — перенесёте и всю историю. Удалите .git — останутся только текущие файлы, без единой прошлой версии.

§3GitHub: сайт с копией репозитория

GitHub — веб-сервис, принадлежащий Microsoft. Его основная работа — хранить копию вашего репозитория на своих серверах и отдавать её по запросу. Всё остальное надстроено вокруг этой копии и к самому Git отношения не имеет.

Что добавляет сервис:

  • страницу проекта, где код виден в браузере, без установки чего-либо;
  • задачи (Issues) с метками, исполнителями и обсуждением;
  • pull request — предложение внести изменения, с ревью и замечаниями к конкретным строкам;
  • права доступа: кто может читать, кто писать, кто менять настройки;
  • канбан-доски в Projects, автоматические проверки в Actions, публикацию сайта через Pages.

Ни одной из этих возможностей в Git нет. Pull request, метки и доски придуманы сервисом; Git о них не знает и работает точно так же, если вы ими не пользуетесь.

§5Как они соединяются

После публикации проекта существуют две самостоятельные копии: локальная — в папке на вашем компьютере, удалённая — на GitHub. Это не одна папка, открытая из двух мест, и не автоматическая синхронизация наподобие облачного диска.

Ваш компьютер Локальный репозиторий папка проекта/.git

Здесь вы меняете файлы, создаёте коммиты и ветки.

push → по сети ← fetch / pull
Сервер GitHub Удалённый репозиторий github.com/имя/проект

Здесь команда видит опубликованные коммиты и обсуждает работу.

Git запоминает адрес второй копии под коротким именем. Обычно это имя origin. Оно не означает «GitHub» и не является особым сервером — это просто удобная подпись к адресу. Один локальный репозиторий может быть связан сразу с несколькими удалёнными: например, с GitHub и с сервером колледжа.

1Commit

Git сохраняет состояние локально. Интернет не участвует.

2Push

Git отправляет готовые коммиты по адресу origin.

3GitHub

Сервис показывает их в браузере и даёт команде обсудить правки.

4Fetch / Pull

Git получает коммиты, которые появились в удалённой копии.

Важно: commit и push — не одно действие

Commit записывает версию в историю на вашем компьютере. Push переносит уже созданные коммиты в удалённый репозиторий. Поэтому сообщение «Everything up-to-date» не означает, что изменения сохранены: возможно, вы ещё не сделали коммит.

§6Что работает без интернета

Проверка простая: если действие касается файлов и истории, которые уже лежат на диске, его выполняет Git. Если нужно обратиться к сайту или обменяться данными с другой копией, понадобится сеть.

Сценарий: поезд без связи

Вы едете три часа без интернета. За это время можно изменить проект, сделать несколько осмысленных коммитов, создать ветку и вернуться к прошлой версии. Все эти действия накопятся в локальной истории. Когда связь появится, один push отправит новые коммиты на GitHub.

Но увидеть свежую работу одногруппника вы не сможете: его коммитов ещё нет в вашей копии. Сначала Git должен получить их через fetch или pull. Распределённость даёт автономность, но не телепатию между компьютерами.

§7Откуда взялся GitHub

Git уже существовал три года, когда появился GitHub. Сам Git решал задачу хранения и обмена историей, но не давал удобного публичного места, где можно открыть проект в браузере, увидеть автора каждой правки и обсудить её. В 2008 году вокруг этой потребности вырос отдельный сервис.

2008апрель
Публичный запуск GitHub

Проект Тома Престона-Вернера, Криса Ванстрата и Пи-Джея Хайетта выходит из закрытого тестирования. Репозиторий становится не только адресом для обмена, но и страницей для совместной работы.

2009первые инструменты
Вокруг кода появляется рабочее пространство

GitHub добавляет комментарии к коммитам, поиск, Pages и другие функции, которых нет в самом Git.

2018Microsoft
Сервис покупает Microsoft

Microsoft завершает приобретение GitHub. Git при этом не становится продуктом Microsoft: он остаётся отдельным открытым проектом.

Два проекта, две судьбы

Git — свободная программа, которую развивает сообщество; её можно установить без аккаунта. GitHub — коммерческий веб-сервис со своими владельцем, тарифами и правилами. Покупка GitHub компанией Microsoft не меняет устройство Git и не даёт Microsoft контроля над вашими локальными репозиториями.

§8Сервисов много, Git один

GitHub популярен, но он не является обязательной частью Git. Удалённый репозиторий можно разместить на другом сервисе, на сервере организации и даже в другой папке на том же компьютере. Команды commit, branch, merge, push и pull от этого не меняются.

Переезд возможен потому, что главная ценность — история коммитов — находится внутри Git-репозитория, а не только в интерфейсе сайта. Однако задачи, pull request, комментарии и настройки доступа принадлежат конкретному сервису; их перенос требует отдельных инструментов.

§9Разбор привычных фраз

В разговоре короткие формулировки удобны, но за ними скрываются разные действия. Переведём несколько фраз на точный язык.

«Я сохранил работу в GitHub»

Что, вероятно, произошлоСначала Git создал локальный коммит, затем отправил его на GitHub командой push.

«Скачай проект с гита»

Точный переводСклонируй Git-репозиторий с GitHub или другого указанного сервиса.

«У меня Git не открывается»

Нужно уточнитьНе открывается сайт GitHub, панель Source Control в VS Code или сама папка репозитория?

«Я удалил ветку»

Нужно уточнитьЛокальную ветку в Git, удалённую ветку на GitHub или обе? Это два разных указателя.

«Коммит уже в облаке»

Точный переводКоммит есть в удалённом репозитории; значит, после commit был выполнен push.

«GitHub сделал коммит»

Что произошлоПользователь изменил файл в браузере, а GitHub создал коммит в размещённом у него Git-репозитории.

§10Частые заблуждения

Обычно думаютБез аккаунта GitHub нельзя сделать коммит.
На самом делеКоммит создаёт Git на компьютере. Для него нужны имя и электронная почта автора, но не вход на сайт.
Обычно думаютФайлы на компьютере постоянно синхронизируются с GitHub.
На самом делеКопии обмениваются только коммитами и только после явных команд push, fetch или pull.
Обычно думаютУдалили проект на GitHub — потеряли всё.
На самом делеПолный локальный репозиторий сохраняет файлы и историю. Его можно опубликовать заново на любом сервисе.
Обычно думаютGitHub — надёжная резервная копия всех текущих файлов.
На самом делеТуда попадают только закоммиченные и отправленные изменения. Незакоммиченный файл существует лишь на вашем диске.
Обычно думаютGitHub принадлежит автору Git.
На самом делеGit создал Линус Торвальдс; GitHub основала другая команда, а с 2018 года сервис принадлежит Microsoft.
Обычно думаютДля Git обязательно нужен GitHub.
На самом делеGit работает сам по себе. Удалённую копию можно не заводить или хранить на другом сервисе.

§11Проверьте себя

Вы сделали коммит без интернета. Где он находится?

Только в локальном репозитории, в истории внутри .git. Когда появится сеть, его можно отправить в удалённую копию командой push.

После push в GitHub появился код. Кто выполнил отправку, а кто принял данные?

Отправку выполнила программа Git на вашем компьютере. GitHub принял коммиты, сохранил их в удалённом репозитории и показал через веб-интерфейс.

Почему удаление репозитория на GitHub не обязано уничтожить историю проекта?

Потому что Git распределённый: полная история есть в каждой полноценной локальной копии. Если хотя бы одна сохранилась, из неё можно создать новый удалённый репозиторий.

Можно ли заменить GitHub на GitLab и продолжить пользоваться Git?

Да. Нужно изменить адрес удалённого репозитория и перенести коммиты. Локальные команды и история останутся теми же; отдельно придётся перенести задачи, pull request и настройки сервиса.

Одногруппник сделал коммит и отправил его на GitHub. Почему вы пока его не видите?

Ваша локальная копия ещё не получила новые данные. Нужно выполнить fetch или pull; простого открытия папки недостаточно.

Что точнее: «GitHub хранит проект» или «GitHub хранит удалённую копию Git-репозитория»?

Вторая формулировка. Она напоминает, что есть отдельная локальная копия, а история создаётся механизмами Git и может храниться не только на GitHub.

Итог главы

Git отвечает за историю проекта и работает на вашем компьютере. GitHub хранит одну из удалённых копий и добавляет браузер, доступы, задачи, pull request, проверки и публикацию. Между двумя копиями нет непрерывной синхронизации: Git явно отправляет коммиты через push и получает их через fetch или pull. Поэтому Git продолжает работать без интернета, а GitHub можно заменить другим сервисом.
