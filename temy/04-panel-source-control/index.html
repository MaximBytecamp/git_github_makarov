§1Что показывает панель и зачем она нужна

Проводник показывает файлы, которые лежат в папке. По нему нельзя узнать, какие файлы изменены после последнего коммита и что войдёт в историю при нажатии Commit. Это показывает панель Source Control: она сравнивает папку проекта с последним коммитом и выводит разницу.

Зачем это нужно в работе

  • Перед сохранением видно, что уходит в историю. Панель показывает список изменённых файлов до нажатия кнопки, поэтому случайно закоммитить черновик или чужой файл сложнее.
  • Список изменений составляется автоматически. После рабочего дня по нему видно, какие файлы менялись. По этому же списку пишут пояснение к коммиту.
  • Лишний файл виден до коммита. Файл с паролем, ключом или большой архив заметен в списке до отправки.
На полях: что понадобится

Для работы нужны Git и VS Code, установленные по главе 1.3. Проверка: команда git --version печатает номер версии. Проект главы называется proba-git и состоит из одного файла.

1Первый коммит по шагам

§2Шаг 1. Открыть папку проекта

Git ведёт историю отдельной папки, поэтому сначала папку проекта открывают в VS Code.

Создаём пустую папку proba-git там, где хранятся ваши проекты. В VS Code открываем её: меню File → Open Folder или кнопка Open Folder в проводнике, если в окне ещё не открыта ни одна папка.

Откроется системное окно выбора папки. Находим в нём proba-git и подтверждаем кнопкой Select FolderOpen. Затем открываем панель Source Control — значком с развилкой на левой полосе или сочетанием CtrlCmd + Shift + G.

Initialize Repository заводит историю на вашем компьютере. Publish to GitHub дополнительно создаёт копию проекта на GitHub. Нажимаем Initialize Repository, публикация разобрана в модуле 4.

На полях: не открывайте домашнюю папку целиком

Если нажать Initialize Repository в папке Documents или в домашней папке пользователя, Git начнёт отслеживать все файлы в ней: документы, загрузки и настройки. Поэтому открывают папку конкретного проекта.

Что получилось.Папка proba-git открыта в VS Code, панель Source Control предлагает завести в ней репозиторий.

Наводим курсор на строку файла в списке, не нажимая. Справа от имени появляются три значка. Они относятся к файлу в этой строке.

Что делает каждый из трёх:

ЗначокПодсказка при наведенииЧто делает
Листок со стрелкойOpen FileОткрывает файл в редакторе как обычно. Ничего не меняет
Круговая стрелкаDiscard ChangesВозвращает файл к состоянию последнего коммита: ваши правки стираются

Разница между двумя разделами панели:

  • Changes — всё, что изменилось в папке. В коммит это не попадёт.

Путь одного файла

1 · Правка Вы изменили файл и сохранили его в редакторе. в истории ничего нет
2 · Changes Файл появился в списке изменений. в коммит не войдёт
3 · Staged Вы нажали плюс: файл отобран для следующего коммита. войдёт в коммит
4 · Commit Нажата кнопка Commit — состояние сохранено в историю. записано в историю

Сохранение файла в редакторе (CtrlCmd + S) — это только шаг 1, коммит ещё не сделан. Пока не пройдены шаги 3 и 4, вернуться к этой версии нельзя.

Ассоциация: посылка на почте

В жизни

Для посылки выбирают вещи, складывают их в коробку, заклеивают и подписывают. Остальные вещи остаются дома.

В VS Code

Changes — вещи дома. Плюс у файла кладёт его в коробку (Staged Changes). Поле Message — подпись на коробке. Кнопка Commit заклеивает её: содержимое зафиксировано.

Где не совпадаетПосылка уезжает из дома, а файл остаётся в папке, и его можно править дальше. Коммит сохраняет состояние файла на момент коммита.

Что получилось.privet.html в разделе Staged Changes с буквой A — он войдёт в коммит.

§7Шаг 6. Написать пояснение

Щёлкаем в поле Message над кнопкой и пишем одной строкой, что сделано: «Добавил страницу с приветствием». Сообщения вроде «правки» или «коммит» не сообщают, что изменилось.

Без пояснения коммит не создаётся: VS Code открывает вкладку COMMIT_EDITMSG и ждёт текст. По пояснениям в истории ищут, когда и зачем менялся файл.

Что получилось.В поле Message пояснение «Добавил страницу с приветствием».

§10Справка: буквы у имён файлов

Буквы U и M встретились в шагах главы. Остальные три встречаются реже. Каждая буква — первая буква английского слова.

БукваЗначитКогда появляется
U — untrackedНовый файл, Git за ним ещё не следитСоздали файл в папке проекта
M — modifiedФайл был в истории и изменёнОткрыли и поправили существующий файл
D — deletedФайл удалён из папкиУдалили файл, который был в прошлом коммите
A — addedНовый файл уже подготовлен к коммитуНажали плюс у файла с буквой U
R — renamedФайл переименованСменили имя файла, содержимое осталось прежним

При переименовании панель сначала показывает два изменения: удалённый старый файл (D) и новый файл (U). После отбора Git сравнивает содержимое и, если оно совпадает, показывает переименование.

§11Справка: счётчик, строка состояния, меню

Синий кружок на значке Source Control — сколько файлов изменилось с последнего коммита. Ноль означает, что папка совпадает с историей.

Строка состояния внизу окна. Слева имя текущей ветки и значок обмена с сервером. Три состояния, которые встречаются чаще всего:

Что видноЧто это значит
main и значок облакаВсё сохранено в историю, копии на GitHub у проекта нет
main*В папке есть изменения, которых нет в истории: коммит не сделан
main ⟳ 3↓ 2↑Проект связан с GitHub: два ваших коммита не отправлены, три чужих не забраны

Третье состояние появится в модуле 4, когда проект окажется на сайте. На стрелки смотрят перед началом работы: сначала забирают чужие коммиты, потом делают свои. Так реже приходится разбирать слияния.

Меню с остальными командами находится под значком с тремя точками справа от слова CHANGES. Там собраны все команды Git, которые понадобятся дальше.

Пункт менюЧто делаетВ какой главе
Pull, Push, FetchОбмен коммитами с копией на GitHubМодуль 4
CloneСкачать чужой репозиторий себеГлава 2.2
Commit → Undo Last CommitОтменить последний коммит, вернув файлы в подготовленныеГлава 2.6

3Проверка себя

§12Частые вопросы

Обычно думаютФайл сохранён в редакторе — значит, он в истории.
На самом делеСохранение меняет файл на диске. В историю он попадёт после подготовки и коммита: это шаги 5–7 из этой главы.
Обычно думаютКнопка Commit отправляет работу на GitHub.
На самом делеCommit сохраняет состояние на вашем компьютере. За отправку отвечает Sync Changes, и до неё на сайте ничего нового нет.
Обычно думаютПанель пустая — значит, Git не работает.
На самом делеПустая панель означает, что папка совпадает с последним коммитом. Так панель выглядит сразу после коммита, например на шаге 7.
Обычно думаютЕсли нажать плюс у всех файлов, будет быстрее.
На самом делеВ коммит попадут и черновики, и случайные файлы. Отбор нужен, чтобы коммит содержал одну законченную правку.

§13Проверьте себя

На значке Source Control стоит цифра 4. Что это означает?

Четыре файла в папке проекта отличаются от последнего коммита: изменены, созданы или удалены.

Чем Changes отличается от Staged Changes?

Changes — изменения в папке, не отобранные в коммит. Staged Changes — изменения, отобранные плюсом; при нажатии Commit сохраняются только они. Разделение позволяет записать в коммит часть правок.

Рядом с файлом стоит буква U. Что это за файл и что с ним делать?

Файл новый: он лежит в папке, но в истории его ещё нет. Чтобы он попал в проект, нажмите плюс — буква сменится на A, файл окажется в Staged Changes, — и сделайте коммит. Если файл попал в папку случайно, его можно удалить или внести в .gitignore.

Почему при первом клике по новому файлу открылся сам файл без окна сравнения?

У нового файла нет прошлой версии. Окно сравнения открывается у файлов, которые уже есть в истории, как на шаге 8.

Вы сделали коммит, но на GitHub изменений не видно. Почему?

Коммит сохраняется на вашем компьютере. Чтобы он оказался на сайте, нужна отправка: кнопка Sync Changes или пункт Push в меню. Пока проект не опубликован, в строке состояния стоит значок облака.

Что произойдёт, если нажать круговую стрелку у изменённого файла?

Файл вернётся к состоянию последнего коммита, а все правки после него исчезнут без возможности вернуть. Git их не сохранял, поэтому восстанавливать нечего. Если правки ещё понадобятся, перед отменой их сохраняют коммитом.

§14Шпаргалка по главе

Порядок действий открыть папку Initialize Repository создать файл → плюс пояснение → Commit
Открыть панель CtrlCmd+Shift+G значок с развилкой слева
Два списка Changes — изменилось в папке Staged Changes — войдёт в коммит
Буквы U — новый файл M — изменён D — удалён A — подготовлен
Кнопки у файла плюс — подготовить минус — вернуть из подготовленных круговая стрелка — отменить правки
Строка состояния main — текущая ветка main* — есть несохранённое облако — проект не опубликован

Итог главы

Шаги главы составляют основной порядок работы с Git: открыть папку, завести репозиторий, создать файл, посмотреть изменения, отобрать их плюсом, написать пояснение, нажать Commit. Панель показывает разницу между папкой проекта и последним коммитом: изменённые файлы попадают в Changes, отобранные — в Staged Changes, и в историю уходит только второй список. Буква справа от имени показывает, что случилось с файлом, счётчик на значке — сколько файлов разошлось с историей, строка состояния — на какой вы ветке и опубликован ли проект. В следующей главе разобраны два способа получить репозиторий: завести его в своей папке и клонировать готовый.
