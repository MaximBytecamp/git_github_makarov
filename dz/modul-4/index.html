1Аккаунт и безопасная связь

Главы 4.1–4.2. Сначала проверим, что GitHub покажет преподавателю и какой адрес будет у созданного проекта.

Шаг 1. Оформить профиль

  1. Откройте GitHub в браузере и войдите в свой аккаунт. Щёлкните по аватару → Your profile.
  2. Вкладка Overview должна показывать ваш логин. В Edit profile заполните Name или Bio одной нейтральной строкой о том, что вы изучаете разработку. Не указывайте адрес, номер телефона или пароль.
  3. Вернитесь на страницу профиля и обновите её.
Снимок 1

Страница вашего профиля GitHub: видны логин, имя или Bio и вкладка Overview.

Подпись: «Рисунок 1 — Оформленный профиль GitHub»

Шаг 2. Проверить способ входа

В VS Code откройте палитру команд Ctrl + Shift + P и найдите GitHub: Sign in. Если рядом написано, что вы уже вошли, ничего не переавторизовывайте. Если VS Code просит открыть браузер, завершите вход только через страницу GitHub. Токен вручную создавать и вставлять в задание не нужно.

Почему так

GitHub подтверждает доступ через браузер или SSH-ключ. Токен похож на пароль: его нельзя показывать на снимке, в сообщении, в README и тем более записывать в файл проекта.

Снимок 2

VS Code после входа: виден ваш аккаунт GitHub в меню Accounts либо сообщение, что вход уже выполнен. Токенов и паролей на снимке быть не должно.

Подпись: «Рисунок 2 — VS Code связан с аккаунтом GitHub»

2Новый репозиторий и README

Главы 4.1 и 4.3. Создадим пустой проект на GitHub, затем наполним его локально. Название сделает ссылку на вашу работу понятной.

Шаг 1. Создать репозиторий

  1. На GitHub нажмите + в правом верхнем углу → New repository.
  2. В поле Repository name напишите dz-github-4-familiya, заменив familiya своей фамилией латиницей. Например: dz-github-4-ivanov.
  3. Поставьте Public. Не отмечайте Add a README file, .gitignore и лицензию: первый README мы создадим локально и опубликуем сами.
  4. Нажмите Create repository. Скопируйте HTTPS-адрес из блока Quick setup; он заканчивается на .git.
Снимок 3

Страница нового пустого репозитория: видны владелец, имя dz-github-4-familiya и HTTPS-адрес, оканчивающийся на .git.

Подпись: «Рисунок 3 — Создан пустой репозиторий на GitHub»

Шаг 2. Создать локальную папку и первый коммит

Создайте на компьютере отдельную папку dz-github-4-familiya и откройте её в VS Code. В панели Source Control выберите Initialize Repository. После этого создайте два файла. В README.md вставьте шаблон, а в about.md — одну строку о проекте.

В панели Source Control отберите оба файла плюсом и сделайте коммит Создал описание проекта. Затем откройте терминал в этой папке и добавьте адрес своего пустого репозитория. Удалённая запись origin хранит адрес репозитория, а origin/main позже станет локальной записью о ветке main на GitHub. Вместо адреса в образце вставьте свой HTTPS-адрес.

В выводе git remote -v один и тот же адрес будет дважды: для получения (fetch) и отправки (push).

Снимок 4

VS Code: открыт README с заголовком, списком и ссылкой; в терминале виден ответ git remote -v с вашим адресом.

Подпись: «Рисунок 4 — Локальный проект связан с пустым репозиторием»

4Push, Fetch и Pull

Глава 4.4. Теперь коммиты появятся по обе стороны: один создадим локально, другой — через веб-интерфейс GitHub. Важно заметить, когда файл уже есть на сервере, но ещё отсутствует в вашей папке.

Шаг 1. Отправить локальный коммит

В about.md после первой строки добавьте:

Сделайте коммит Уточнил цель проекта. До отправки в графе main будет выше origin/main. Нажмите отдельную кнопку Push, не Sync Changes, и обновите сайт GitHub.

Снимок 8

GitHub: открыт about.md, в нём две строки; сверху видны сообщение и короткий хеш последнего коммита «Уточнил цель проекта».

Подпись: «Рисунок 8 — Локальный коммит отправлен на GitHub»

Шаг 2. Создать коммит на GitHub

  1. На странице репозитория нажмите Add file → Create new file.
  2. В имени файла напишите news.md, в поле содержимого — Новости проекта..
  3. В поле сообщения напишите Добавил новость через GitHub и нажмите Commit changes. В поле ветки должна быть main.
  4. Вернитесь в VS Code. Файла news.md в проводнике пока нет: GitHub получил его, но ваша локальная история ещё не знает о коммите.
Снимок 9

GitHub: открыт news.md, сверху видно сообщение коммита «Добавил новость через GitHub».

Подпись: «Рисунок 9 — Коммит создан на GitHub»

Шаг 3. Получить сведения через Fetch

В VS Code выполните Git: Fetch через палитру команд. Откройте граф. В нём появится origin/main с новым коммитом, но локальная main останется на предыдущей вершине. Файл news.md всё ещё отсутствует в проводнике: Fetch скачивает сведения и коммиты, но не включает их в текущую ветку.

Снимок 10

Граф VS Code после Fetch: origin/main стоит на коммите «Добавил новость через GitHub», а main — ниже; news.md нет в проводнике.

Подпись: «Рисунок 10 — Fetch обновил сведения, но не файлы»

Шаг 4. Включить полученный коммит

У вас нет своих новых коммитов после последнего Push, поэтому можно выполнить Git: Pull. После Pull откройте news.md: файл появился в рабочей папке. В графе main и origin/main снова стоят на одном коммите.

Снимок 11

VS Code после Pull: открыт news.md со строкой «Новости проекта.», а метки main и origin/main совпадают.

Подпись: «Рисунок 11 — Pull получил файл и передвинул ветку»

5Когда ветки разошлись

Глава 4.5. Создадим по одному новому коммиту локально и на GitHub. Они затронут разные файлы, поэтому слияние пройдёт без конфликта. Не используйте Force Push.

Шаг 1. Сделать свой локальный коммит

В about.md допишите третью строку История проекта проверена в графе Git. и сделайте коммит Добавил итог проекта. Не отправляйте его. В графе локальная main будет на один коммит впереди origin/main.

Снимок 12

Граф VS Code: main выше origin/main, верхний локальный коммит называется «Добавил итог проекта».

Подпись: «Рисунок 12 — Есть один локальный исходящий коммит»

Шаг 2. Сделать независимый коммит на сайте

Не закрывая VS Code, откройте GitHub. Через Add file → Create new file создайте contacts.md со строкой Связь: репозиторий на GitHub.. Сообщение коммита — Добавил контакты через GitHub, ветка — main.

Вернитесь в VS Code и нажмите Push. Git отклонит отправку: на сервере появился коммит, которого нет в вашей локальной истории. Сначала нужно получить и включить этот коммит. Нажмите Cancel, если VS Code предлагает Sync, и не выбирайте Force Push.

Снимок 13

Вывод Git в VS Code либо терминал с отказом Push: видны rejected и fetch first или non-fast-forward.

Подпись: «Рисунок 13 — Push отклонён из-за нового коммита на GitHub»

Шаг 3. Fetch, Merge и обычный Push

  1. Выполните Git: Fetch. В графе теперь две линии: на одной «Добавил итог проекта», на другой «Добавил контакты через GitHub».
  2. Проверьте, что текущая ветка — main. Через палитру выберите Git: Merge…, затем origin/main. Не выбирайте собственную main.
  3. Git создаст коммит слияния. Откройте about.md и contacts.md: оба файла должны быть в рабочей папке.
  4. Нажмите обычный Push. Теперь удалённый коммит входит в историю вашей ветки, поэтому отправка будет fast-forward.
Снимок 14

Граф VS Code после Push: сверху коммит слияния соединяет две линии; метки main и origin/main находятся на нём. В проводнике есть contacts.md.

Подпись: «Рисунок 14 — Расходящиеся истории объединены без Force Push»

6Итоговая проверка и сдача

Проверьте репозиторий

  • В репозитории есть README.md, about.md, news.md, contacts.md и screenshots/home.png.
  • На главной странице GitHub README показывает изображение.
  • В истории на GitHub видны ваши коммиты, веб-коммиты и коммит слияния.
  • В VS Code нет незакоммиченных файлов и нет счётчиков входящих/исходящих коммитов.
  • В репозитории нет токена, ключа, .env, личного документа или пароля.

Первый ответ должен начинаться с ## main...origin/main и не содержать ahead или behind. Второй показывает линии истории, третий — адрес вашего репозитория.

Если что-то пошло не так
  • Push отклонён. Не используйте Force Push. Выполните Fetch, посмотрите граф и включите origin/main через merge либо обратитесь к преподавателю, если появились незнакомые изменения.
  • Картинка не видна в README. Сверьте путь, имя и регистр букв: screenshots/home.png отличается от Screenshots/Home.png.
  • VS Code просит войти снова. Войдите через официальный браузерный экран GitHub. Не присылайте токен и не добавляйте его в проект.
  • В графе нет раздела GRAPH. Откройте Source Control и выполните палитру Git: Show Graph; если команды нет, используйте git log --oneline --graph --all в терминале.
