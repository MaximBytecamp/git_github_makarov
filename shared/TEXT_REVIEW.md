# Проверка текста перед публикацией

Прогоняется по каждой новой главе, практике и разделу до того, как страница
попадёт в оглавление. Порядок: сначала грепы, потом сплошная вычитка, потом
проверка утверждений. Пропускать второй шаг нельзя — он находит больше, чем
первый.

---

## 1. Каким должен быть текст

Взрослая лекция для студентов, которые тему ещё не знают. Связное объяснение
от абзаца к абзацу: термин вводится точно и сразу объясняется, без ссылок
вперёд и без пересказа того, что будет позже.

В трудных местах после точного термина — аналогия и конкретный пример,
и прямое объяснение, для чего это нужно. Каждую команду в блоке и каждое поле
на кадре разбирать в тексте, а не оставлять без пояснения.

Вводный абзац главы пишется как описание содержания («В этой главе разобрано…»),
а не как обращение к читателю. Абзац заканчивается фактом, а не выводом
сверх сказанного.

**Не добавлять:** сквозную историю, нарастающую «главную мысль», вопросы
к студенту («сначала ответьте сами»), придуманные названия блоков.

## 3. Сплошная вычитка: то, что грепы не ловят

Грепы находят известные строки. Всё остальное — только чтением. На практикуме
по `explain` в справочнике MongoDB из 16 найденных мест грепы дали 2.

Текст вытаскивается без разметки и читается подряд:

```bash
python3 - <<'PY'
import re, io, html
s = io.open('temy/NN-slug/index.html', encoding='utf-8').read()
s = s[s.index('<main'):s.index('</main>')]
s = re.sub(r'<(pre|style|script).*?</\1>', ' ', s, flags=re.S)
s = re.sub(r'<[^>]+>', '\n', s)
for line in s.split('\n'):
    t = html.unescape(line).strip()
    if len(t) > 25: print(t)
PY
```

Что искать глазами:

- **оценочный эпитет вместо указания**: «Главный экран разбора», «Главная
  плитка работы», «Вариант Б интереснее», «У варианта А плохи обе цифры»
  → назвать предмет: «Под заголовком Execution Stats идут восемь плиток»;
- **связка-усилитель «и есть то, что…»**: «Три верхних числа и есть то, что
  записывается в отчёт» → «Три верхних числа записываются в отчёт»;
- **пояснение-опровержение через двоеточие**: «Sort (0) — не ошибка: …»,
  «дело не в способе: …» — та же антитеза «X, а не Y», только замаскированная
  → «Sort (0) означает, что …»;
- **одушевление программы**: «план умеет показывать сам», «инструмент ничего
  не знает о вашей базе», «команда придирчива к оболочке»;
- **разговорное вместо точного**: «стенд просто работает», «вставлять можно
  куда угодно»;
- **висящее деепричастие** в подписях: «числа попадают в отчёт, не открывая
  файл» → «числа видны сразу, открывать файл не нужно»;
- **морализаторская подводка** перед разделом и «красивый» вывод в конце
  абзаца — обобщение сверх сказанного;
- **нагнетание про время и цену**: «стоит минуту», «за секунды», «час чужого
  времени».

Подписи к кадрам и ячейки таблиц проверять наравне с абзацами: слоп садится
туда чаще, потому что их читают по диагонали.

## 4. Снисходительный тон

Отдельная проверка. Конструкция, уже введённая в прошлых главах, не объясняется
«на пальцах» заново — это читается как недоверие к аудитории. Перед правкой
полезно посмотреть, каким языком о ней говорили раньше:

```bash
grep -rn 'индекс\|HEAD\|origin/main' temy/0*/index.html | head -40
```

```bash
grep -rniE 'готовый ответ|это как|можно сказать|как бы|на самом деле всё просто' temy/*/index.html
```

## 5. Правдивость утверждений

Ни один из грепов выше этого не видит.

**Все модальные утверждения** — каждое проверяется контрпримером: сделать
наоборот и запустить.

```bash
grep -ohE '[^.<>]{0,55}(должн|нельзя|обязательн|всегда|никогда|единственн)[^.<>]{0,55}' temy/NN-slug/index.html
```

Если контрпример даёт тот же результат, на странице стоит не правило,
а соглашение — и писать его надо соглашением с причиной.

**Все упоминания одной конструкции подряд**: если два раздела определяют
одно и то же по-разному, один из них неточен.

```bash
python3 - <<'PY'
import re, io, html, sys
s = io.open('temy/NN-slug/index.html', encoding='utf-8').read()
body = s[s.index('<main'):s.index('</main>')]
for term in ['ветк', 'HEAD', 'индекс']:
    print('\n───── ' + term)
    for n, sec in enumerate(re.split(r'(?=<h2)', body)[1:], 1):
        t = html.unescape(re.sub(r'<[^>]+>', ' ', re.sub(r'<pre.*?</pre>', '', sec, flags=re.S)))
        for sent in re.split(r'(?<=[.!?])\s+', re.sub(r'\s+', ' ', t)):
            if term in sent and len(sent) > 30:
                print('  %3d  %s' % (n, sent.strip()[:108]))
PY
```

## 7. Что этот аудит вылавливает кроме стилистики

Каждый прогон, помимо формулировок, вскрывает содержательные дефекты —
их править отдельно и называть в отчёте:

- подсказка к заданию говорит про другой объект, чем само задание, или
  называет неверное число;
- ожидаемый вывод в тексте не совпадает с тем, что даёт прогон;
- два соседних раздела противоречат друг другу либо повторяют одну мысль;
- выдуманная точность в цифрах;
- термин введён без расшифровки;
- имя файла в шапке блока кода не совпадает с именем в тексте;
- один и тот же термин пишется по-разному в разных главах;
- кадр VS Code снят на другом состоянии стенда, чем показывает текст рядом
  (другое число на кнопке Sync Changes, другой верхний коммит);
- кадры с ответом стоят внутри задания, которое студент должен решить сам
  (найдено в задаче 3 практикума: таблица с пропусками, а под ней снимки
  с заполненными числами).

## 8. Что ловилось в этом справочнике

Найдено при правке модулей 1–3 (сентябрь–октябрь 2026). Каждый пункт хотя бы
раз доходил до пользователя и возвращался на доработку. Грепы ниже — первый
проход, большинство пунктов ловится только чтением.

```bash
A=temy/NN-slug/index.html
grep -niE 'работаем на|вы пишете|а теперь добавьте|представим|простыми словами|отсюда точное|теперь видно|остаётся решить|именно|не просто|вовсе|и есть то|и есть ревью|не случайно|обо что спотыка|это нормально|экономят|боязно|выглядит странно|учебн(ый|ое|ая|ом|ого|ых)' "$A"
grep -niE 'на самом деле' "$A" | grep -v 'myth__yes'
grep -nE '(нет|недоступен|сгорел|пропал|потеряли) — ' "$A"
grep -noE '<p class="step-done">[^<]*<b>[^<]*</b>[^<]*(нужно|надо|делают|проверяют|правило)[^<]*' "$A"
```

### Подводка и вводный абзац

- **Обращение к воображению и сценка вместо описания.** «Вы пишете курсовую…»,
  «А теперь добавьте к задаче второго человека», «Вчера страница работала,
  сегодня нет», «Строка выглядит странно, трогать боязно» → описание ситуации
  в третьем лице: «Без системы контроля версий прошлые варианты сохраняют
  копиями», «Страница перестала работать после недавних правок».
- **Риторические вопросы подряд внутри абзаца.** «Чем … отличается? Кто и когда
  добавил? Где та версия?» → одно утверждение: «По таким копиям нельзя быстро
  узнать, чем …, кто и когда … и в каком файле …».
- **«Работаем на проекте X»** → «В главе используется проект X».
- **Подводка-мораль** «Кнопки удобны, но…», «Читать полезно, но…» → факт:
  «В инструкциях и на форумах историю показывают командами».

### Внутри абзаца

- **Драматичное тире вместо условия.** «Сервер недоступен — нельзя…»,
  «Интернета нет — работа продолжается», «Сервер сгорел — проект
  восстанавливается» → «Когда сервер недоступен, …», «Без интернета …»,
  «Если сервер вышел из строя, …».
- **Нагнетание и мораль в конце.** «смерть диска означает потерю всего»,
  «десять минут сейчас экономят разбирательства потом», «Ни одна из этих
  ситуаций не решается копиями папок» → факт с причиной или ничего.
- **Утешение после факта.** «Номер версии будет свежее — это нормально»,
  «… — обе стороны довольны», «и это первое, обо что спотыкаются» → только факт.
- **Связки-усилители.** «именно», «вовсе», «не просто», «и есть то, что»,
  «Отсюда точное определение», «Теперь видно, как», «Остаётся решить» —
  удалить или заменить прямым утверждением.
- **Разговорное и образное.** «Простыми словами, reset отматывает историю»,
  «Что было за вчера», «за пару кликов» → «Reset возвращает историю
  к указанному коммиту», «Коммиты со вчерашнего дня».
- **Одушевление.** «Git не знает, что такое GitHub», «Сервис узнаёт о проекте»,
  «Название у него ещё толком нет» → «Для Git GitHub — адрес ещё одной копии».
- **Слово «учебный»** («учебный проект», «учебное издание», «учебный
  компьютер») не используется. Исключение — текст внутри файлов стенда,
  который виден на кадрах.

### Заголовки

- **Лозунг, ритм, сюжет.** «Сервисов много, Git один», «Апрель 2005: десять
  дней», «Ядро Linux и чужой инструмент», «Кто развивает Git на самом деле»
  → название содержания: «Другие сервисы для репозиториев», «Ядро Linux
  и BitKeeper», «Кто развивает Git».
- **Шаги называются глаголом одного вида.** «Шаг 9. Отказ в переключении»
  среди «Создать», «Сделать», «Вернуться» → «Шаг 9. Получить отказ
  в переключении».
- **Подзаголовок режима называет итог**, а не механизм:
  «Режим --mixed: правка остаётся только в файле».

### Последовательность шагов

- **Обещание в подводке совпадает с содержимым.** «показывает в двух местах»,
  а дальше перечислены три — исправлять подводку.
- **Одно определение термина на главу.** Если в §1 ветка — «линия коммитов»,
  в шаге 3 не вводится второе «точное определение»; шаг 3 говорит, как Git
  её хранит.
- **Нет ссылок вперёд внутри главы** («обе ветки будут показаны в шаге 6»).
  Ссылки на следующие главы и модули допустимы одной фразой.
- **Перед каждым блоком команды или кадром — строка подводки.** Блок, который
  идёт сразу после другого блока без текста, получает строку «Проверяем, …»
  или «Переключаемся на main командой:».
- **Действие описано раньше его результата.** Фраза про окно VS Code стоит
  после действия, которое окно открывает.
- **«Что получилось» — только результат.** Правила («перед коммитом ветку
  проверяют…») переносятся в текст шага.
- **Имена на схемах совпадают с текстом и соседними главами** (`forma`
  на схеме 3.1 при `forma-kontaktov` в 3.2 — ошибка).

### Повторы и наглядность

- **Одно состояние — один способ показа.** Если результат шага виден на кадре,
  не дублировать его таблицей «где / что там», двумя командами проверки
  и абзацем пересказа. Пользователь назвал это «очень много повторов».
- **Состояние файлов показывается кадром окна целиком**: слева Source Control,
  справа открытый файл (1100×640, плотность 2). Таблица — только в итоге
  нескольких опытов.
- **Работа с ветками сопровождается схемой после каждого изменения**: какие
  коммиты, на каком стоит каждая ветка, куда указывает HEAD. Схема
  без подписи-пересказа: подпись называет одно изменение.
- **После каждого примера назван результат**: что убрано, что осталось.
  Без этого сравнение режимов (`--soft`/`--mixed`/`--hard`) непонятно.

### Правдивость

- Ответ команды в тексте получен запуском на стенде. Хеши в соседних главах
  относятся к одному стенду; если стенд пересобран, это сказано в отчёте.
- Факт без источника («разработчики ядра работали в самолётах задолго
  до интернета») удаляется.
- Ссылка на следующую главу в итоге проверяется по оглавлению: глава могла
  уйти в `chernoviki/`.
